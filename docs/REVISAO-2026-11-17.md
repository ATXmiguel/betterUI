## 3. Erros engolidos sem registro (médio, 30 min)

São 55 blocos `catch` no projeto. O fail-open (princípio 1) justifica não quebrar a página, mas um erro engolido
em silêncio é um bug que você nunca vai ver. Seis `catch` estão totalmente vazios:

| Local | O que protege | Pergunta |
| --- | --- | --- |
| `fetchers/session.ts:47` | leitura do menu em `extractMenuComponent` | Se o menu mudar, "Ver Notas" simplesmente não aparece e você não sabe por quê. Melhor candidato para um `log.debug` |
| `fetchers/collect.ts:143` | gravação parcial do cache | Falha de armazenamento some sem aviso |
| `storage/cache.ts:75` | leitura do cache | Cache corrompido vira "sem dados" |
| `selectors/map.ts:330` e `:348` | resolução de seletores | Quando um seletor lança erro, você não descobre qual |
| `lib/safe.ts:26` | o próprio wrapper `safe()` | Provavelmente intencional; confira se o `console.debug` da linha 24 é suficiente |

Como fazer: em cada um, decida "engolir é correto?" e, se for, acrescente `log.debug('o que falhou', err)`
(o `log` só imprime com a flag de debug ligada, então não polui o aluno).
Conferir: `grep -rn "catch" src | wc -l` antes e depois.
